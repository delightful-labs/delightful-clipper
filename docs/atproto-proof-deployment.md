# AT Protocol proof deployment

The `research/atproto-jwt-proof` branch uses a configured Jazz test app rather
than the generated, 14-day app used by ordinary deploy previews. Its branch
context applies to both deploy previews and branch deploys. Production deployment
through this proof command is rejected.

Netlify project: `delightful-clipper` (`dfc858ef-fc08-4038-b0dd-48d6b081dbc1`).

Set these variables specifically for `research/atproto-jwt-proof`, with Builds
scope. Do not set them globally or in the production context:

| Variable                 | Value                                                       |
| ------------------------ | ----------------------------------------------------------- |
| `PUBLIC_JAZZ_APP_ID`     | `922a7e18-89b5-49d3-9f5b-f4fe20c48a9b`                      |
| `PUBLIC_JAZZ_SERVER_URL` | Jazz Cloud sync URL, normally `https://v2.sync.jazz.tools/` |
| `JAZZ_ADMIN_SECRET`      | Dedicated test app admin secret; mark as secret             |

The script requires this exact test app ID and maps the service coordinates to the Jazz deployment variables,
including the account registry. Missing proof credentials stop the build before
any Jazz deployment. Administration credentials are removed before the frontend
build. No credentials belong in this document or Git.

## Postgres storage qualification — 2026-11-06

The user approved trying Netlify Database and installing `@netlify/database`
2.0.3, `pg` 8.23.1 and development types `@types/pg` 8.23.1. This replaces the
proposed local SQLite approach. No ORM or custom auth table shapes were added.

`createAuthDatabase` creates a Better Auth-compatible Postgres pool using
Netlify's `getConnectionString()` by default; its caller owns pool shutdown.
There is no auth HTTP endpoint or application-lifetime wiring yet.

The generated migration at `netlify/database/migrations/20261106000100_auth.sql`
contains the library-defined `user`, `session`, `account`, `verification`,
`atprotoSession`, `atprotoState` and `jwks` tables and their indexes. It was
generated by Better Auth 1.7.18 with the installed AT Protocol and JWT plugins.
The generator refuses non-local database URLs and does not execute SQL.
From the repository root, against an empty local Postgres database:

```sh
AUTH_MIGRATION_LOCAL_DATABASE_URL='<local connection string>' node --experimental-strip-types apps/web/tooling/generate-auth-migration.ts
```

Generation refuses to overwrite the initial migration. Do not alter it once a
hosted deployment has applied it; future schema changes need new migrations.
Netlify applies the migration on deployment, including production if this work
is eventually merged and deployed there. No hosted migration was applied here.

An isolated local test used `@netlify/database-dev` 1.0.1 already bundled in the
installed Netlify CLI 27.15.0. It applied the migration to a temporary local
database, exercised the real Better Auth and AT Protocol adapters, then closed
the pool and database and reopened the same directory with a fresh auth instance.
User and app-session records, OAuth state/session records and JWT signing keys
survived that restart. This qualifies local adapter/storage behavior, not real
OAuth, concurrency, production Postgres, Netlify provisioning or cross-device login.
