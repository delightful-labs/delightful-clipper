# Repository working agreements

- Run user-facing dev servers on the network (`0.0.0.0`) in a named tmux window. Provide a working LAN URL and ensure the browser’s Jazz URL is reachable there. Preserve existing authorities; localhost-only servers are for isolated tests or explicit user requests.

- All subsequent work must use a feature branch and a pull request targeting `main`. Do not push directly to `main`. The specification-baseline reset was a one-time explicit user instruction.
- Use Conventional Commits PR titles: `type(scope): description` (scope optional; `!` before the colon for breaking changes). The PR title workflow validates this format.
- Do not merge a PR without explicit user authorization. Do not configure branch protection or change repository settings unless requested.
- Follow `specs/001-jazz-clipper/spec.md`, `plan.md`, `design-decisions.md`, and `implementation-handoff.md`. Keep accepted scope cuts intact.
- The workspace tooling, account integration and private library root are implemented; URL-first capture, dedicated reader workflows and bounded inline offline raster images are implemented; annotations and broader product/release qualification remain open. The prototype and isolated proof scripts are archived on `archive/pre-jazz-rewrite-2026-11-02`; do not restore its legacy dependencies or source as the implementation baseline.
- Treat the main thread as the UI thread. Application/domain state machines, Jazz operations, persistence, validation, hashing, projections, search preparation and background processing belong in Web Workers. UI code renders bounded, ready-to-render views and forwards user intent. Do not substitute async functions, caching, debouncing or smaller main-thread tasks for this boundary. Keep DOM, focus, viewport/selection measurement and native UI effects on the UI thread; isolate any genuinely Window-only compatibility API behind a narrow, explicit adapter with no domain decisions. Preserve XState ownership, cancellation, account scopes and local/remote/unknown-write settlement across the message boundary. See [docs/memory/worker-runtime.md](docs/memory/worker-runtime.md).
- Use the selected strict TypeScript, Svelte 5, XState, DLF identity/recovery, DUI presentation and i18next boundaries. Model state/resource ownership before implementing asynchronous workflows.
- XState memory is binding: read [docs/memory/xstate.md](docs/memory/xstate.md) before designing, changing or reviewing workflows, persistence, actor lifetimes or notification handlers. Apply its ownership rules before implementation; renaming or extracting callbacks is not a substitute for modeling decisions and data flow in the owning chart.
- Obtain explicit user approval before installing a new third-party dependency. Explain its purpose and alternatives first; a package mentioned in the technical plan is not installation approval. An explicit user request to install a named package supplies that approval.
- Clipper owns domain schemas/policies and data operations; DLF owns reusable identity/recovery behavior; DUI owns generic presentation. Do not silently adopt a sibling repository's constitution or copy its domain models.
- Offline restart is a usability gate, including AT Protocol-connected and existing-account sign-in. Online login/reload is insufficient. Prove reopening the same cached library after a complete browser-process restart with app/auth/Jazz endpoints unreachable, preserve locally acknowledged offline edits through another restart, and verify reconciliation after reconnect. Exercise expired provider credentials as a separate case; do not substitute a fresh empty local account or call the integration usable before this evidence exists.
- Separate local persistence from remote acceptance and retain unknown-write recovery. Never claim privacy, offline availability or platform support without the corresponding evidence.
- Complete and report checks appropriate to each PR. Isolated investigation results do not substitute for validation of the actual implementation.
- Keep implementation scoped to the current user request; Add Link immediately saves a URL article through the same operation that optionally accepts supplied content. A dedicated Web Worker machine processes articles missing content one at a time. Do not reintroduce a separate intake graph/journal or main-thread capture orchestration.
- Localization memory is binding: read [docs/memory/localization.md](docs/memory/localization.md) before changing user-visible copy. Never add a catalog string (including a new plural form or changed wording) without explicit user approval first. The proposal must give its usage reason and confirm, after searching, why no existing string/action/noun would work. General feature authorization is not string approval; do not bypass this with hardcoded text or inline fallbacks.
- First web-app use must open a usable local library without signup, following Finance's DLF/Jazz `initial: 'local-first'` integration. Reuse the persisted local identity; recovery/restoration is optional, and remote connectivity must not gate local readiness. Do not reintroduce a Create account screen as the initial product gate.
- Extension capture requires a confirmed connection to an existing account. A toolbar click without that connection opens a trusted sign-in popup; after successful DLF restoration the original gesture may continue. A silently created/persisted local identity alone is not sign-in. Model admission, popup lifetime, restoration confirmation and native account verification with XState. Keep web no-signup behavior unchanged and credentials out of page code.
- Use DUI default presentation for the app shell and controls, following Finance's composition patterns. Keep Clipper CSS limited to structural layout; do not add a separate palette, card skin, font system or decorative styling around DUI components.
- Use DUI input components for user-entered fields. A silently initialized local Jazz identity must not expose Sign out; that control is reserved for an explicitly signed-in identity. Keep recovery/restoration available without signing out of local mode.
- Saved readers are dedicated SvelteKit pages linked by document URL, not inline library panels. Keep session/capture actors in the application layout, use normal anchors for navigation, and qualify direct/offline reader URL loads.
- Keep Svelte formatting enabled in Oxfmt. Run `pnpm format` and `pnpm format:check` for component changes; format script, markup and CSS, with readable multiline declarations and blank lines between CSS rule blocks.
- Prefer readable, localized state names (`meta.name`) for workflow feedback. Put outcome selection in explicit states and transitions; selectors should project the active name rather than reconstructing a message from failure/status flags. Forward dynamic feedback from its owning child machine.
- Workflow status/error messages belong to the state machines. Call the localization library directly in the owning machine and expose ready-to-render text/severity; Svelte components must not map machine status/error codes to translation keys.
- Workflow decisions must appear in statechart guards and transitions. Mutation/actions and invoked I/O leaves perform a defined operation; they must not select the next workflow with mode flags or conditional side effects. Splitting a conditional callback into differently named functions is not a state-driven refactor. Keep checks and writes under the same transaction owner when modeling mutation branches. Ordinary validation, protocol decoding and pure data projection may remain functions.
- Give domain eligibility rules descriptive predicate names and reuse them across guards/adapters. Compose shallow named checks or guard clauses rather than nested boolean expressions; distinguish missing articles, pending content, URL matching and operation ownership explicitly.
- Scope/lifetime enforcement belongs at actor admission/result consumption and shared transaction admission/commit boundaries. Do not scatter pre/post `isCurrent` assertions around repository leaf operations; keep reads bound to their original DB/library and let owners discard stale results and drain issued writes.
- Use Zod schemas for untrusted input shapes and bounds, and infer the corresponding DTO types. Keep domain relationships and workflow eligibility as named predicates/actor guards. Preserve caller error mapping and representation-sensitive limits; never expose rejected input or raw Zod errors in product responses or diagnostics.
- Compose related Zod schemas from their canonical schemas with `pick`, `omit`, `extend` and `shape` references instead of redeclaring shared fields and constraints. Derive DTO types with `z.infer`. Apply whole-record refinements at the appropriate composed boundary so related forms share field validation without inheriting unrelated invariants.
