# Add Link and minimal saved reader

The application runtime owns one library actor for the current account binding after canonical-root readiness. The actor owns extraction, duplicate lookup, automatic save preparation/publication, remote receipts, list subscription and reader loading. Presentation sends events and renders localized states. Sign-out, account replacement and shutdown invalidate visible content immediately, cancel read/network work, and drain issued local writes before releasing identity. Remote acceptance never blocks local availability or teardown.

URL identity is a conservative normalized final HTTP(S) URL without its fragment. Submitted URL, redirect observations and canonical candidate remain provenance. Canonical candidates do not merge articles. A library-scoped deterministic UUID identifies this destination; immutable publication and an existing-operation check prevent replacement and uncertain-write replay. A blocked/unknown operation offers reconciliation/Open, never an automatic second insert. Source metadata is atomically published with native text/HTML bytes under owner-only parent policies.

The current flow is Add Link → automatic local save → explicit Open on a dedicated SvelteKit `/articles/[id]` page. There is no preview confirmation or separate Save action. Sanitized HTML is retained as native bytes and rendered through the shared display sanitizer, with exact literal-text fallback. Static SVG and native details/summary are supported under the bounded [content policy](design-decisions.md#retained-disclosure-and-svg-content). Remote images are not loaded; image acquisition, annotations and full reader controls remain open. The production service-worker shell and direct offline reader startup are implemented and qualified in Chromium. Fetching a new public URL still requires network access; local publication can complete with the authority offline.

Validation includes real-authority source-policy/atomic publication checks, deterministic actor cancellation/drain/uncertainty/rejection tests, and UI capture/duplicate/restart/restored-profile evidence. Test fixtures may intercept the browser gateway response; transport/extractor and hosted gateway proofs remain separately recorded rather than being inferred from a fixture.

Read actors hand content to their explicit consumer and retain only a non-content outcome at terminal states. The consuming actor clears reader/candidate/list content on scope loss; the library machine spawns its storage child, sends SHUTDOWN in its stopping state and waits for the child's local settlement before releasing it. Remote receipts are observed separately and never delay session teardown. Generic storage records retain their existing schema; optional source rows add an owner-only immutable document reference. This is an additive schema deployment.

Current boundaries: pre-save state is ephemeral; no durable network-intake resumption, failed-capture link-only entries, accepted canonical aliases, concurrent-capture reconciliation, images or organization. Repeated/uncertain same-ID publications are blocked and offer Open rather than replacing content. See [tasks.md](tasks.md) for the latest 235-unit/17-browser-test evidence and remaining work.

This includes scope replacement and drain, terminal read cleanup, uncertain-write non-replay, late rejection, owner/orphan source policies, duplicate identity, and UI offline-save/process-restart/restored-profile sync. Hosted immutable Netlify deploy `6ae9f5e6fa289d07cbb359f5` (code commit `aae2821`) passes real Chromium account creation, authenticated extraction of example.com, explicit save/global acceptance, reader/Open original, reload and fragment duplicate detection. Preparation is an invoked machine with explicit resolving, identifying-resolved, checking-resolved-document, checking-resolved-intent, extracting, identifying-extracted, checking-extracted-document and checking-extracted-intent states. Each completion rechecks account scope before advancing. Jazz/HTTP adapters expose one operation at a time; they do not sequence preparation or manage actor lifetimes. A typed spawn binding selects the concrete storage logic while the library machine owns creation, active/stopping states, completion/error handling and child removal. Cancellation/account loss is tested at all eight preparation boundaries, including late-result suppression. Save-drain tests assert that the child remains owned until settlement and is removed afterward.

## Reader, sync and worker ownership cleanup

The library invokes the record reader directly with a generation-bound report destination. Document, text, byte asset and optional source metadata are separate read states; optional metadata failure/invalidity preserves readable text. Reader departure stops its invocation and stale generations cannot reopen a replaced/closed view. Terminal read context clears content, capabilities and report destinations. Jazz adapters expose only individual reads, not an actor-start/await/follow-up-query wrapper.

One sync supervisor owns per-article instances of the shared storage sync machine. Completion, replacement and account shutdown clear receipt context and remove child references; late reports are ignored. Stopping an observer does not undo a local write or cancel an SDK write. Underlying SDK wait promises may settle later; they cannot publish status into the closed binding. Saved writes draining during shutdown do not attach new sync observers.

The parser worker machine owns running/stopping/settled states, the ten-second deadline and reply/error/cancellation precedence. A reply remains provisional until worker exit. Cancellation wins through termination; timeout/error outcomes also wait for exit. The Node bridge only creates the worker, forwards events and exposes termination/listener cleanup. Normal settlement awaits exit; forced parent stop requests best-effort emergency termination. Tests use a simulated clock for worker races and retain real worker extraction/cancellation checks.

`pnpm verify` passes with 190 tests across 21 files, including optional-metadata fallback, stale readers, concurrent/replaced/closed sync observers, child receipt cleanup, worker startup/error/exit/timeout/cancellation and late results. All eight Chromium tests pass after the cleanup, including offline save, full browser restart and restored-profile sync. Hosted qualification is repeated on the updated PR preview.
