# Session/private-root implementation design

This batch adds only account creation/restoration/recovery and the immutable private library root. The browser layout owns one coordinator for its lifetime. DLF supplies session acquisition/readiness and the recovery/restoration adapters and workflows. Clipper supplies its root data capability; DUI supplies form/status controls; i18next supplies English strings.

The coordinator owns opening → running → closing. Opening cannot be cancelled by discarding a promise: shutdown during opening waits for the returned host, then closes it. Running owns the session observer and explicit creating/restoring/logout invocations; observations during those invocations are recorded but do not abandon the issued identity operation. DLF restoration is a child statechart with parse/prepare/mutate/read stages; only the signed-out state accepts a restoration phrase. The coordinator clears its phrase after validation; the DLF child clears transient credentials. No actor inspection, diagnostics or persistence receives credentials.

For a ready account/client binding, the coordinator reads the canonical root locally, rejects incompatible records, issues only the identical immutable root ensure, waits for local persistence, then observes global acceptance separately. Only locally confirmed state is usable. Identity loss/replacement immediately removes old library/recovery views; old SDK work remains owned by the SDK session lifecycle, and stale completions cannot enter a replacement binding. During explicit identity mutation the observer remains attached, but routing waits for that operation's actual result. Shutdown/close waits through DLF session ownership. Interrupted immutable-root ensures are repeatable; general data writes are not introduced.

Every invoked I/O has an error outcome: open failure, session unavailable, invalid restore, identity mutation failure, root conflict, local persistence failure, sync rejection/pending and close failure. Retrying a compatible immutable root uses the same account ID and payload. No arbitrary workspace allocation, captured content or note writes exist yet. Root policies enforce authenticated owner and canonical row IDs, with no ordinary root deletion.

Verification targets: machine shutdown during acquisition, rejection before local persistence, separate local/global readiness, stale binding completion, invalid restoration, authority rejection of alternate/foreign roots, concurrent same-account ensure, and real browser reload/restoration with authority disconnected. The service-worker/full offline-shell milestone remains later work; this batch must not claim it.

## Validation and remaining limits

`pnpm verify` passes: archive verification, formatting, lint, strict TypeScript/Svelte checks (zero errors/warnings), seven coordinator/native-policy tests, and the Netlify production build. Two Chromium integration tests pass against a disposable real Jazz authority, including account creation, reload, independent-profile restoration, authority shutdown/restart, and invalid restoration without account creation. Browser recovery artifacts are disabled.

The current Jazz/Vite build emits the same approximately 19.3 MB WASM binary at both the application asset URL and the SDK worker asset URL, plus a large application chunk. The explicit runtime URL prevents a missing root-relative WASM request. Asset deduplication and download optimization remain follow-up work; this build is not evidence of a deployed Netlify service, offline app-shell support, or non-Chromium support.
